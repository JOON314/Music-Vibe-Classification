**요약**
- 8개 피처(auditory spectrum L1, 대역 에너지 2개, flux, MFCC 1·4, sharpness, slope)는 플레이리스트 곡의 **93~100%가 DEAM 범위 밖**.
  `audspec_lengthL1norm`은 평균이 약 2,200σ 떨어져 있음 → 곡의 차이가 아니라 **계산 방식·단위(스케일) 차이**.
- 곡별 RMS z-score: 플레이리스트 중앙값 **444**, DEAM 중앙값 0.74 (DEAM 99% 분위 2.66).
- 결과: 플레이리스트 원시 예측값의 표준편차가 19~59 (DEAM 척도는 1~9) → 모델이 학습 범위 밖으로 크게 외삽.
  이 때문에 학습을 다시 할 때마다 Arousal 순위가 거의 뒤집힘. `scale_to_10`이 이를 0~10에 눌러 담아 겉보기엔 정상처럼 보였음.

**해결 방안**
- (권장) 2단계를 실제 openSMILE(`opensmile` 파이썬 패키지, ComParE_2016 LLD)로 교체. 24개 피처가 모두 같은 이름으로 있음
  (MFCC만 `mfcc_sma[k]` ↔ `pcm_fftMag_mfcc_sma[k]` 이름 차이). DEAM과 같은 도구라 시프트가 거의 사라질 것으로 예상.
  맥(Apple Silicon)에서 설치·동작 확인함. 곡 2개로 실제 분포를 확인한 뒤 적용.
- (대안) librosa 피처를 DEAM 분포에 맞춰 보정 — 근거가 약해 비추천.

## 2. `scale_to_10` (플레이리스트 내 min-max) vs DEAM 원래 척도

| | 현재: min-max 0~10 | 대안: DEAM 척도(1~9) 그대로 |
|---|---|---|
| 의미 | 이 플레이리스트 안에서의 **상대 순위** | 곡 자체의 **절대** 분위기 |
| 같은 곡의 결과 | 같이 넣은 곡에 따라 바뀜 | 항상 같음 |
| 강제 극단값 | 최소곡은 항상 0(→ -1), 최대곡은 항상 10(→ +1) | 없음 |
| 1곡짜리 플레이리스트 | 항상 0 → **무조건 "차분한 & 우울한"** | 정상 |
| 2곡짜리 | 무조건 한 곡은 -1, 한 곡은 +1 | 정상 |
| `(x-5)/5`, 임계값 ±0.2 와의 관계 | 원래 1~9 척도용으로 설계된 변환을 0~10에 적용 | 설계 의도와 일치 |
| 도메인 시프트가 있는 지금 | 이상한 원시값을 가려줌 | 원시값이 1~9를 크게 벗어나 대부분 ±1로 잘림 |

DEAM 라벨에 같은 임계값을 적용하면: Valence 담담한 57% / 우울한 25% / 밝은 18%, Arousal 포근한 51% / 차분한 30% / 활기찬 19%.
→ **권장: openSMILE로 시프트를 해결한 뒤 DEAM 척도 그대로 사용.** 시프트를 그대로 둔다면 지금의 min-max가 차라리 나음.

## 3. 3단계 재현성
